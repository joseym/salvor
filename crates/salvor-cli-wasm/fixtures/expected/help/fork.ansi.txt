Fork a graph run from a node boundary into a NEW run, refusing to re-execute a recorded write the operator has not acknowledged

[1m[4mUsage:[0m [1msalvor fork[0m [OPTIONS] [1m--from-node[0m <NODE> [1m--graph[0m <FILE> <RUN_ID>

[1m[4mArguments:[0m
  <RUN_ID>
          The origin run id (a UUID) to fork

[1m[4mOptions:[0m
      [1m--from-node[0m <NODE>
          The node boundary to restart the fork from: the fork re-walks from this node, carrying the origin's events below it as an identical prefix

      [1m--store[0m <PATH>
          Path to the SQLite event store.
          
          The precedence is flag, then the `SALVOR_STORE` environment variable, then the default: an explicit `--store` wins, else `SALVOR_STORE`, else `./salvor.db`.
          
          [env: SALVOR_STORE=]
          [default: ./salvor.db]

      [1m--graph[0m <FILE>
          Path to the graph document (JSON) the origin ran. Re-supplied the same way a graph resume re-supplies it (the log records only the hash); its hash must match the recorded one, since a fork reuses the origin's graph unchanged

      [1m--agent[0m <FILE>
          An agent definition (TOML) the graph's `agent` nodes reference. Repeatable, exactly as `graph run` and a graph `resume` take them

      [1m--acknowledge-writes[0m <SEQ,SEQ|all>
          Acknowledge the writes the re-walked segment would re-fire: a comma-separated list of origin log positions (`4,7`), or `all` to acknowledge the full hazard set. Recorded permanently into the child's fork origin. Omit when the fork boundary sits before any write

      [1m--dry-run[0m
          Print what the fork WOULD do (the hazard list and the would-be prefix summary) without creating a run

  [1m-h[0m, [1m--help[0m
          Print help (see a summary with '-h')
