Salvor CLI: run, resume, list, history, and replay for durable agent runs

[1m[4mUsage:[0m [1msalvor[0m [OPTIONS] <COMMAND>

[1m[4mCommands:[0m
  [1mrun[0m          Start a fresh run of an agent
  [1mresume[0m       Continue an existing run: resume a parked one, or recover a crashed one
  [1mwake[0m         Wake every run whose durable timer has come due, then exit. Nothing wakes a sleeping run on its own, so run this from cron when no server is doing it
  [1mfork[0m         Fork a graph run from a node boundary into a NEW run, refusing to re-execute a recorded write the operator has not acknowledged
  [1mresolve[0m      Record the completion of a dangling write by hand, after verifying it
  [1mabandon[0m      Abandon a run: retire it by hand without finishing or failing it, for a run that is dead forever or no longer worth carrying
  [1mlist[0m         List runs in the store, newest activity last. Filters narrow what is printed; with none, every run is listed
  [1mcompletions[0m  Print a shell completion script for `salvor` on stdout
  [1mhistory[0m      Print a run's event log
  [1mreplay[0m       Re-derive a run's state from its log without executing anything. The only mode; nothing is ever executed
  [1manchor[0m       Take an anchor over this store: one line per run naming how many events it holds and the hash that commits to them. Keep the file somewhere the store cannot reach
  [1mverify[0m       Check this store against an anchor taken earlier: every anchored run must still hold, unchanged, the events it was anchored at
  [1mserve[0m        Run the control-plane HTTP + server-sent-events server over the store
  [1mbuild[0m        Build the whole product from a salvor checkout: the web dashboard, then the release binary that embeds it
  [1magent[0m        Author-time agent definition tools: print the content hash a graph `agent` node has to reference. Reads no store and drives no run
  [1mgraph[0m        Graph document tools. `edit`, `validate` and `schema` are author-time: they read no store and drive no run. `run` drives a document over the store, exactly as `salvor run` drives an agent run
  [1mhelp[0m         Print this message or the help of the given subcommand(s)

[1m[4mOptions:[0m
      [1m--store[0m <PATH>
          Path to the SQLite event store.
          
          The precedence is flag, then the `SALVOR_STORE` environment variable, then the default: an explicit `--store` wins, else `SALVOR_STORE`, else `./salvor.db`.
          
          [env: SALVOR_STORE=]
          [default: ./salvor.db]

      [1m--caller[0m <NAME>
          The name to record as the caller on the events this command writes.
          
          A verb that starts, resumes, resolves, or abandons a run records who asked for it. Left unset, that is the operating system user this process runs as; this flag names someone else, for a wrapper script or a job runner that knows better than the account it happens to run under. The precedence is the flag, then `SALVOR_CALLER`, then the operating system user, which `salvor_cli::caller_name` resolves.
          
          It is a label on the events, never a credential: nothing checks it and nothing is granted by it. A store written by whoever can write the file carries whatever name they chose, which is why the server takes its own name from a verified token instead.
          
          [env: SALVOR_CALLER=]

  [1m-h[0m, [1m--help[0m
          Print help (see a summary with '-h')

  [1m-V[0m, [1m--version[0m
          Print version
