A ceiling is shown only for a run that actually crossed one, because the ceiling reaches the log solely as a BudgetExceeded event carrying the limit and the observed value. Every other run's ceiling is simply not on record here, so it reads unknown. Tokens are exact from the fold; dollars are an estimate from a maintained price table keyed by the model id on each completion — a run whose model is not in the table degrades to tokens only rather than quoting a number that silently omits spend.

A forked run's total would include usage it never incurred. A fork's log is seeded with a copy of its origin's events, and those events carry the origin's real ModelCallCompleted usage — so folding the fork's whole log counts that spend a second time. The fold itself is right; it sums events genuinely in the log. What would be missing is a control plane that de-duplicates by origin when totals are added together — not a concern this build hits yet, since forking has no runtime behind it here.

One bar per hour, counting events by their own recorded_at — not by the run's last touch. A run that worked for three hours spans three bars, which is what a chart shaped like time has to mean. This lives on Spend because it needs every event's timestamp, which means folding every log — the same cost Spend already pays for a dollar figure, and the cost the run list refuses to pay.

An hour filters the run list to the runs it can name — which is not the same set the bar counted. The bar knows every event's own hour because Spend folded the logs; the list knows only last, so hour: means last active in this hour. A run that worked through 09:00 and ran on until 11:00 is in the 09:00 bar and not in the 09:00 filter. Each hour says both numbers before you click it, and an hour the list cannot name is drawn but is not a button.
